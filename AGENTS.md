
## Learned User Preferences

- Never start the dev server; the user always does this manually
- Add a file path comment at the top of every source file (e.g. `// src/components/sidebar/Sidebar.tsx`)
- Use Biome for linting/formatting — not ESLint or Prettier. The working tree is CRLF, so format touched files with `npx biome format --write --line-ending=crlf <files>`
- Prefer CSS variables + SCSS over Tailwind; no Tailwind dependency in this project
- Use Cascadia Code (not JetBrains Mono) as the monospace font
- No emojis in responses unless explicitly requested
- Prefer KISS, YAGNI, SOLID; propose incremental improvements and understand existing code first
- Always check available MCP servers and use them when relevant
- Commit only when asked, in logical batches (one commit per feature or section)
- Keep this file in step with the code: when a change makes a fact here wrong (stack, window, storage, shortcuts, release flow), fix that line in the same change. It is edited by hand

## Releases and changelog

- The changelog is written for the people using the app, not for developers: one short line per change, in plain language about what they see or can now do. No file, function or library names. The same text is shown in the GitHub release and in the app's update dialog
- Sections, in this order, with empty ones left out: `### New`, `### Changed`, `### Fixes`, `### Other`. Keep a release to a handful of lines; merge small tweaks into one line
- Add lines under `## Unreleased` at the top of `CHANGELOG.md` in the same change that ships the feature or fix, not at release time. The section heading is just `## vX.Y.Z` (no title, no date) once released
- Never edit version numbers by hand. Versions follow semver: patch = fixes only, minor = anything new, major = a change that breaks existing vaults
- To release, and only when the user asks: `npm version patch|minor|major` (or an exact number), then `git push --follow-tags`, then publish the draft release on GitHub. `npm version` (via `scripts/release.mjs`) checks the changelog format, bumps `package.json` and `src-tauri`, turns `## Unreleased` into `## vX.Y.Z`, commits "Release vX.Y.Z" and tags it. Never tag or push unasked
- `.github/workflows/release.yml` builds the signed Windows installer on a `v*` tag and opens a draft release whose notes are that CHANGELOG section. Installed apps only see published releases

## Learned Workspace Facts

- Project: Graphene (renamed FlowVault → Graphite → Graphene) — a Tauri v2 desktop app for markdown notes with code blocks, nested folders and a trash; disk root: `D:\graphene`; Tauri identifier: `com.graphene.app`; GitHub: `MogensenJesse/graphene` (remote: `https://github.com/MogensenJesse/graphene.git`)
- Stack: Tauri v2 (plugins: fs, clipboard-manager, dialog, opener, updater, window-state, single-instance), React 19, TypeScript 7, Vite 8, SCSS + CSS custom properties, nanoid, react-markdown (remark-gfm, remark-breaks, rehype-highlight), Biome 2. Frontmatter is parsed by a small parser in `src/lib/fileFormat.ts` (no gray-matter)
- Design language and SCSS system borrowed from `D:\image-optimizer` (React + JSX, no TypeScript — reference for styles only)
- Palette in `src/assets/styles/base/_variables.scss` (pastel, cool): `$light` #c8ccd6, `$night` #0c0d10, `$onyx` #0f1013, `$green` #96dfa8, `$yellow` #e8cf82, `$red` #e8909a, `$blue` #89b8e8; radii `$radius-sm` 3px, `$radius-md` 7px, `$radius-lg` 12px, plus `--border-radius-row` 8px. Components use the semantic tokens (`--color-background-primary`, `--color-text-tertiary`, `--color-background-hover`, …), not the raw SCSS colors. These are the dark theme's values; see Themes below
- Themes: `:root` holds the dark tokens and `:root[data-theme="light"]` (same file) overrides them; `src/lib/theme.ts` (plain functions, no hook: `initTheme` in `main.tsx` before the first render, `setThemePref` from Settings) sets `data-theme` on `<html>` (popups live outside `.app`) and calls the window's `setTheme` so the acrylic backdrop and native scrollbars follow; the one OS-change listener is registered there. The choice is in `localStorage` (`graphene.theme`: system, light, dark). Never put a raw colour in a component's SCSS: tint overlays, scrims, shadows and danger/blue tints are tokens (`--surface-*`, `--shadow-*`, `--rgb-danger`, `--rgb-blue`). The light text colours were checked at 4.5:1 against both paper surfaces; recheck when changing a token. Pasting any new colour that is not a token breaks one of the two themes
- Icons are Lucide (ISC) copied as inline SVG into `src/components/ui/Icon.tsx`, each marked `// lucide: name`; no icon package is bundled
- Layout: `src/components/` is grouped: `ui/` (Icon, Modal, ContextMenu and its provider, Tooltip, WindowControls, `MoreButton` (the "…" menu), `UndoToast` (the Undo bar after a trash), `SidebarToggle`, `InlineInput`, `DatePick`, `Segmented` (a row of buttons, one pressed: the Notes | Tasks tabs and the Settings pickers)), `sidebar/` (Sidebar, SidebarHeader, VaultSwitcher, FolderRow, ItemRow, TaskLists), `note/` (NoteDetail, NoteEditor, toolbar, pickers, find bar, `TaskList` (the checkboxes of the reading view), and the other pieces of one note), `tasks/` (TasksPane, TaskRow, TaskDetail, AddTask: the main pane of the Tasks tab), `dialogs/` (SearchPalette, TrashView, UpdateDialog, SettingsDialog, VaultPicker, VaultUnavailable) and `settings/` (the tabs of SettingsDialog: AppearancePanel, VaultsPanel, AssistantsPanel, AboutPanel). Hooks and `src/lib` stay flat. SCSS stays flat in `src/assets/styles/components/`, one partial per component (`_NoteEditor.scss` is the editor)
- Shared helpers, use them instead of writing the pattern again: `src/lib/paths.ts` (`joinPath`, `relativePath`, `fileName`, `extOf`; always "/"), `src/lib/prefs.ts` (`readPref` / `writePref`, localStorage that never throws, plus the collapsed-folder set), `useEscape` (Escape for a popup; capture mode stops propagation), `useLatest` (a ref to the newest value for long-lived listeners), `InlineInput` (every inline name field: Enter or blur commits, Escape cancels), `useDeleteConfirm` (arm, then confirm; used for items, folders and the trash), `newKinds` (`NEW_KINDS`, `newItemEntries`: the one list behind every "new note / code" button and menu entry), `useImageInsert` (pasting and dropping pictures into the editor)
- State: `useItems` keeps its lists through `useListRef`, whose setter updates the ref at once and runs updaters itself. Updaters must stay pure and every file write goes after the `setItems` call, never inside an updater (StrictMode runs updaters twice)
- Tests: `npm test` (Vitest with `node:assert/strict`, files `src/lib/*.test.ts` and `mcp/*.test.ts`) covers the pure code: tasks (note checkboxes), taskStore, taskFiles, markdownFormat, search, mergeScan, attachments, fileFormat, itemPaths, vaultList, fontPrefs, the per-vault collapsed folders in prefs (with a stubbed `localStorage`), and the MCP tools and server (several vaults, through the protocol). Add a test next to any new pure logic
- Data model (`src/types.ts`): one `Item` type, a markdown note. The kind is derived from the text, never stored (`itemKind` in `src/lib/utils.ts`): "code" starts with a fenced block, else "note". The sidebar filter, icon and counts follow that. Tasks are not notes (see Tasks)
- Tasks are a to-do app of their own, apart from the notes: the Notes | Tasks tabs at the top of the sidebar (`graphene.sidebarTab`, the open view in `graphene.taskView`). Data (`src/lib/taskStore.ts`, pure, tested, shared with the MCP server): lists (`TaskList`: optional `color`, one of six names whose colours are the `--accent-*` tokens, and optional `groupId`), groups, tasks (`title`, `done` / `doneAt`, `important`, `myDay`, `due`, `note`, `steps`, `order`) and steps (one level). `myDay` holds the day it was added and counts only while it equals today, so My Day empties itself; My Day and Important are views (`smartList`), not stored lists. Storage is hidden JSON per vault: `<vault>/.tasks/index.json` (`{ version, groups, lists }`) and `<vault>/.tasks/<listId>.json` (`{ version, tasks }`); dot folders are outside the notes scan. Parsing is tolerant: bad entries and repeated ids are dropped, ids that are not safe file names are rejected (an id becomes `<id>.json`), unknown keys are kept so a newer file survives an older app. The default list (`DEFAULT_LIST_ID`, "tasks") always exists in memory and is saved with the first change, so opening a vault writes nothing. Reducers are pure, take ids and timestamps as arguments and return their input when nothing matched. `src/lib/taskFiles.ts` is the file layer over a tiny `TaskFs` (`taskFsTauri.ts` for the app, `mcp/taskFsNode.ts` for the server): every change reads the file, applies the reducer and writes it back through a temp file, one at a time per file, so what the other side wrote in between is merged; a file that is not JSON is copied to `<name>.bak` before it is replaced, and one that cannot be read is never written over. `useTasks(vaultPath)` (in `MainApp`) applies each reducer to memory at once and repeats it on disk, rescans on window focus unless a write of its own is pending or ran meanwhile (the first load is retried), and gives `today`. Order is a rank (`order`, `placeNear` as for notes): a new task goes on top, unranked tasks are newest first, lists and groups without a rank go by name. A task opens in a side pane (`TaskDetail`, `openTaskId`): docked to the right of the list, and floating over it (`@container main (max-width: 739px)`) when the panel is narrow; `TasksPane` finds the open task in any list, so the pane stays when the task is moved, and keys the pane by task id so its uncontrolled fields restart; the pane sits in a slot (`tasks-pane__details`) that slides like the sidebar, so `TasksPane` keeps the last open task while it slides out (and keys that pane "closing", so reopening starts fresh); Enter or Space on a row focuses the pane's title, a click leaves the focus, Escape closes it (committing the field being typed in) and returns the focus to the row; deleting one shows an `UndoToast` (`restoreTask` puts it back with its rank); moving a task to another list writes the new file before it leaves the old one. The checkboxes inside notes stay plain Markdown: `toggleTaskAt` (`src/lib/tasks.ts`, by the offset react-markdown reports for the `<li>`, never the Nth checkbox), `NOTE_COMPONENTS` in `note/TaskList.tsx`, and in the editor `continueTask` and `shiftTaskIndent` (`markdownFormat.ts`). Switching to the Tasks tab (`handleTab` in `App`) saves the editor first, brings the note back in reading view and clears the picked folder, so the Del key cannot reach a folder that is out of sight; `showNotes` switches back when a note is opened or created from elsewhere (Ctrl+K, the window menu). Ctrl+Shift+T switches tabs; Ctrl+N in the Tasks tab focuses the Add box. The date picker is `ui/DatePick` (a button over an invisible `<input type="date">`, opened with `showPicker`). A new task eases in (`justAdded`, the id `addTask` returns), and a task that leaves the open list (ticked, deleted, moved, changed from elsewhere) folds away for `ROW_LEAVE_MS` at its old place: a layout effect compares this render's open rows with the last one's (a switch of view is not a leaving, so `App` keys `TasksPane` by vault) and keeps the gone ones as `.task-row--leaving` rows, which are `inert` and carry no `data-sort-*` attributes so a drag cannot target them
- Storage: file-based vaults, each a user-chosen folder (config at `AppData/graphene/config.json` through Tauri `BaseDirectory.AppData`, see Vaults below). Every item is a `.md` file with YAML frontmatter named `{slug(title)}-{id}.md`; folders are real directories and a folder id is its path relative to the vault; deleted items move to the hidden `<vault>/.trash` and tasks live in the hidden `<vault>/.tasks` (dot folders are ignored by the scan); files that are not `.md` notes with an id are ignored (the v0.1.0 snippet files are no longer converted)
- Vaults: `config.json` is `{ "active": "<open vault path>", "vaultPath": "<mirror>", "vaults": [{ "path", "name", "shared" }] }`; `src/lib/vaultList.ts` (pure, tested) is the only code that reads or writes that shape, for the app (`src/lib/vault.ts`: `loadVaultConfig` / `saveVaultConfig`) and the MCP server alike. The old `{ "vaultPath" }` file loads as one shared vault; unknown keys survive a save. `vaultPath` is a mirror for MCP servers and apps from before several vaults: the open vault if it is shared, else the first shared one, else absent, so an old server is never handed an unshared vault. A vault is identified by its normalised path (`pathKey`: `/`, lower case, no trailing slash); names are unique ignoring case; a vault may not be, contain or sit inside another one (notes would show twice). Removing a vault only takes it off the list. `config.json` is saved whole, in order, to a temp file and renamed, and only from handlers (never from an effect); a file that cannot be parsed is copied to `config.json.bak` and the picker says so, instead of passing for a first run. `useVaults` (in `App`) holds the list: start opens the saved vault or the first whose folder exists (not saved until the user changes something), and `switchTo` / `add` / `remove` call `flushRef` first, so an unsaved edit lands in the vault it was typed in, then change `active`. `MainApp` has `key={vaultPath}`, so a switch resets lists, selection, drafts and effects, and its load effect needs no stale-result guard. `scanVaultRecursive` throws when the vault root cannot be read: a missing folder must not look like an empty vault (a refresh would drop every note and the next save would recreate the folder); `MainApp` then shows `VaultUnavailable`. Collapsed folders are per vault (`graphene.collapsedByVault` in `prefs.ts`; the old `graphene.collapsed` goes to the first vault opened). Sort order, hide-done and the sidebar state are global. `src-tauri/src/lib.rs` allows every vault folder in the fs scope at start (the capability only covers `$HOME/**`, and the folder picker's grant lasts one run), and `pickVaultPath` asks for `recursive`
- MCP server (`mcp/`, `npm run build:mcp` bundles it to `dist-mcp/graphene-mcp.mjs`, run with plain `node`; see the README): a stdio server that reads and writes the vault folders directly with `node:fs`, never through the app, so it works with the app closed. It imports the app's pure modules (`fileFormat`, `itemPaths`, `search`, `taskStore`, `taskFiles`, `utils`, `paths`, `attachments`) so kinds, search and tasks behave the same; `mcp/vault.ts` is the one place with fs code and must keep the scan rules of `scanVaultRecursive` / `readItemFile` in `storage.ts`. The note tools are plain functions in `mcp/tools.ts` and the to-do tools in `mcp/taskTools.ts` (`list_task_lists`, `list_tasks`, `add_task`, `update_task`, `complete_task`, `create_task_list`: they add, change and tick, never delete or rename; tested without the protocol), registered in `mcp/server.ts`; `mcp/main.ts` is the entry. Note file names come from `itemFilePath` (`src/lib/itemPaths.ts`, split out of `storage.ts` for this), so the app and the server never disagree on a name; never write a note's file under another name. Writes only change one note (append, edit a piece of its text with an exact-match replace that fails when the text is missing or ambiguous) or add one (create): no delete, rename or move, and a folder argument goes through `folderPath` (no `..`, no absolute path, no attachments). A note open in a dirty editor is overwritten by the next autosave (see Outside edits). Installing it for other people: `npm run pack:mcpb` (`scripts/pack-mcpb.mjs`, needs `build:mcp` first) stages `dist-mcp/mcpb/` and packs `dist-mcp/graphene.mcpb`, a Claude Desktop extension (manifest written by the script, version from `package.json`, one setting: the notes folder). `tauri.conf.json` runs `build:mcp` and `pack:mcpb` before dev and build (a missing resource file fails the Rust build) and ships both files under `mcp/` as `bundle.resources`; `release.yml` attaches the `.mcpb` to the draft release. In the app, Settings > AI assistants (`AssistantsPanel`, opened from the gear in the sidebar footer) shows how to connect: `src/lib/mcpBundle.ts` finds the shipped files and `src/lib/mcpClients.ts` builds each client's command or JSON. The Claude app keeps its own copy of the `.mcpb` and never updates it (its install record says `source: local`, and the manifest format has no update field), so `src/lib/mcpExtension.ts` remembers the Graphene version at which the extension was last added (a pref) and the dialog shows a notice once Graphene is newer. Clients registered by command or JSON run the script at the install path, which has no version in it, so the app's own updater updates those. The server also reads `GRAPHENE_VAULT`, and an empty or `${...}` value counts as not set, so a client that never filled in the extension's setting gets the shared vaults; with a value (or `--vault`) the server serves only that folder, named after it. With no pin, `mcp/vault.ts` `configVaults` reads `config.json` through `vaultList.ts` on every tool call, so a vault added, renamed or unshared in Graphene applies without restarting the assistant, and keeps the last good list when the file cannot be read for a moment. Only shared vaults exist for the server: tools take an optional `vault` that is a name from `list_vaults` (never a path, so an unshared one cannot be named), reads default to the vault open in Graphene (else the first shared), and when more than one vault is shared the writing tools must name one, so switching vaults in the app cannot redirect a write. Every answer carries `vault` (`search_notes` returns `{ vault, notes }`). `mcp/main.ts` fails only when no vault is configured at all or none can be read. There is no read-only mode on purpose: what an assistant may do is set in the assistant's own permissions, and the tools carry `readOnlyHint` so those can tell reading from writing
- Window: transparent + acrylic, no decorations (custom `WindowControls`), 1366×768 default, min 575×540 (size, position and maximized state are restored by `tauri-plugin-window-state`; a second launch focuses the first window through `tauri-plugin-single-instance`, which must stay the first plugin in `lib.rs`), dev port 1420. The item header is one 52px bar with the window controls laid over its right end; draggable areas use `data-tauri-drag-region`, interactive items inside them need `no-drag` and a z-index above the drag strip
- Sidebar: `App` shows it from `useMediaQuery("(max-width: 799px)")`. A wide window keeps it as the user left it (`graphene.sidebarHidden`); a narrow one starts hidden and the `SidebarToggle` (top-left corner of the note pane, always there) opens it as a floating panel over the note (`app__sidebar--float`, with `app__scrim` behind it) that closes on picking a note or view, Escape or a click on the scrim. Opening and closing is a CSS transition (`$panel-anim` in `base/_variables.scss`, shared with the task details pane: width and margin on a wide window, a slide on a narrow one); the hidden state is `visibility: hidden`, not `display: none`, so it can animate. `--pane-pad` (44px) is the note's left gutter that clears the toggle
- Delete: every path (header "…" menu, Del key, sidebar and right-click menus, drag to Trash) goes through `handleDelete` in `App`, which trashes at once and shows the `UndoToast` (6 s, Undo calls `restoreItem`); only emptying the trash and deleting a folder ask first. Deleting a task has its own Undo toast (see Tasks)
- Fonts: Switzer (Medium + Bold, in `public/fonts`) for UI; Cascadia Code for code. The user's choices (Settings > Appearance) are `src/lib/fontPrefs.ts` (pure parts tested): `graphene.noteFont`, `graphene.codeFont` and `graphene.textSize` in `localStorage`, applied by `applyFontPrefs` (called from `main.tsx` and after each change) as CSS variables on `<html>` that win over the defaults in `_variables.scss`: `--font-note` (reading view), `--font-code` (code blocks, inline code), `--font-editor` (the textarea: follows the note font, else the code font) and `--text-scale`. Only `.note-detail__markdown` and the editor textarea carry `calc(13px * var(--text-scale))`; code and tables inside are `em`-based, and `p { font-size: inherit }` there beats the global `p` size. The chrome (sidebar, menus, tooltips, dialogs) keeps `--font-sans` / `--font-mono` and never scales. A typed font name is quoted (`cleanFontName`) and falls back to the default font; `fontCheck.ts` tells whether it is installed. `useFind.scrollToOffset` mirrors the textarea's font (family, size, weight, style, features) to measure, so a new font property of the editor must be added there
- Shared UI: `Modal` (search palette on Ctrl+K, update dialog), `ContextMenu`, `FolderPicker`, `Tooltip` (the styled tooltip for every icon button and short label, with the shortcut as `keys`; portalled to the body, flips above its button when there is no room below, sets `aria-keyshortcuts`; the only native `title`s left are a sidebar row's note name and the disabled Install button, since disabled buttons get no hover events). Modals set `aria-modal`, and the global shortcuts in `useKeyboardShortcuts` stand down while one is open. Escape handlers for popups run in the capture phase and stop propagation so an open editor does not also close; `Modal` leaves Escape alone while the focus is inside `[data-owns-escape]` (the vault rename input), so that Escape cancels the rename first
- Search (`src/lib/search.ts`, pure): `parseQuery` / `searchItems` rank title hits over text hits and give highlights and a snippet (the sidebar has no type filter: Search is its first row and `type:` narrows a search). Find in note (Ctrl+F) is `src/hooks/useFind.ts`: the read view paints matches with the CSS Custom Highlight API, the editor selects the current match; `App` raises `findSignal` on each press and the open `NoteDetail` or `NoteEditor` shows its `FindBar`. `searchTasks` ranks tasks (title, then note and steps) with the same scoring through one shared ranking; Ctrl+K merges both lists in `SearchPalette`, which marks a task with a check icon and a Task tag and shows its list and due date, and opening one switches to the Tasks tab. `in:` is a note's folder or a task's list name, and `type:task` / `type:note|code` tell them apart
- Outside edits: `useVaultRefresh` (`src/hooks/useVaultRefresh.ts`) rescans the vault when the window gets focus (at most every 5 s) and applies it with `mergeItems` / `mergeFolders` (`src/lib/mergeScan.ts`, pure). Every vault write in `src/lib/storage.ts` goes through `tracked`, and a scan that overlapped one (`writeState` changed) is discarded and retried once, since it can catch a file mid-rename. The open editor copies its note at mount and autosaves, so the merge leaves a dirty editor's note alone and remounts a clean one (`onReopenEditor` bumps `draft.key`); never apply a scan to the editor's note otherwise. The rescan calls `loadVault(path, false)`, so the trash is not re-read (a change made to `.trash` outside Graphene shows after a restart); note files are read 16 at a time (`READ_POOL`) and kept in scan order
- Images: pasted or dropped pictures are saved by `saveImage` (`src/lib/attachmentStore.ts`) into `<vault>/attachments/` and linked relative to the note (`attachmentLink`, `src/lib/attachments.ts`, pure). The scan skips that folder at the vault root and `isReservedFolderName` keeps folders from using the name. The read view's `VaultImage` resolves any `.../attachments/<file>` link by file name (so a stale `../` count still shows) and loads it with `readFile` into a blob URL; there is no asset protocol. `updateItem` / `moveItem` rewrite the `../` depth when a note changes folder depth (`relinkAttachments`). Unused images are deleted only by `sweepUnusedImages` (`storage.ts`), which `useItems.emptyTrash` runs after the trash files are gone: it reads every `.md` in the vault and `.trash` (`readAllNotesText`, throws on any unreadable path so nothing is deleted), and `unusedImages` (pure) picks the files named like `saveImage` names them (`[\w-]{10}.<image ext>`) that no note text mentions by file name; it also skips when a write of ours ran during the scan (`writeState`)
- Right-click: `ContextMenuProvider` (mounted in `App`) owns the one menu and blocks the webview's own. A surface builds `MenuEntry[]` in its `onContextMenu` and calls `useContextMenu().open(e, entries)`, which stops the event; text fields are skipped there and get `textFieldEntries` (`src/lib/textMenu.ts`) from the provider's fallback, with `keepFocus` so the field is not blurred (a blur commits renames). The editor adds a Format submenu through `openText`. Never leave a right-click to the native menu. A menu offers what its surface can do: the fallback menu of `App` (`appEntries`) starts with "New task" in the Tasks tab and with the new note / code entries in the Notes tab, and a task row has its own (`taskEntries` in `TasksPane`: open details, done, important, My Day, due date, move to list, copy title, delete)
- Editor undo: the body textarea is React-controlled, so assigning its value (`setBody`) wipes the browser's undo stack. Edit it only through `replaceText` in `src/hooks/useMarkdownFormat.ts` (`execCommand`, keeps undo). The format rules live in `src/lib/markdownFormat.ts` (`formatText`, pure)
- Drag and drop: `useDragToFolder` (pointer events) drags a note, a folder, a task, a to-do list or a group (`DragSource.kind`: `task` and `taskList` act like a note, next to a peer or as a whole on a container; `taskGroup` like a folder, among siblings only; `useTaskDrag` turns a drop into ranks and moves). The Trash button (a small icon with its count in the sidebar footer, beside the gear) is a drop target through `data-folder-drop-id={TRASH_DROP_ID}`; while a note (not a folder) is dragged it grows to the whole footer row as "Drop to move to Trash" and the gear hides. The Sidebar turns that drop into a delete, never a move. Rows a dragged one can land next to carry `data-sort-kind` / `data-sort-id` (folders also `data-sort-parent`; a folder group is judged by its header); the hook marks the nearest with `data-drop="before|after"` through `src/lib/dragDrop.ts`, the one line style (`_DragDrop.scss`, with `.drag-ghost`) that the task drags use too (a second hook instance lives in `MainApp`; the Sidebar keeps the notes' one). A folder can only be placed among its siblings (never moved to another parent); a note over a note is placed there, over a folder row it moves into the folder. Escape cancels a drag that has started: `startDrag` arms a window `keydown` listener in the capture phase once the drag is active (so a plain press and release is unchanged), which stops the key (an open editor, the details pane or a picker must not also close), clears the ghost, the drop marks and the cursor, and drops nothing; `pointercancel` and a window blur abort the same way, and `swallowNextClick` (`src/lib/dragDrop.ts`) eats the click that follows the release so it cannot open the row the drag started on. Dragging files in from Explorer (`useFileDrop`) cannot be cancelled by the app
- Motion (`src/assets/styles/base/_motion.scss`, imported after the reset): `--ease-out` and `--anim-in` / `--anim-out`, the keyframes (`fade-in`, `pop-in`, `toast-out`, `check-pop`, `row-out`) and the views' fade (`.note-detail`, `.note-detail__markdown` (keyed on the note id), `.note-editor`, `.tasks-pane`, `.trash-view`); `.chevron-turn` is a chevron that turns 90deg when open (folder rows, task groups, the Completed toggle). Everything is short (0.1 to 0.22s), ease-out, and only opacity and transform, except the row fold. Menus, modals, dropdowns, the find bar, the drop overlay and the update pill ease in in CSS only; their exits stay instant, because focus return and menu swapping depend on the element going at once. The context menu fades in without a transform, since it is measured against the window before it is shown. Never put a `transform` on an ancestor of `.drag-ghost` or on a row while a drag may start (the hook measures live rects and the ghost is positioned against the window). `prefers-reduced-motion` zeroes CSS durations in `_reset.scss`; timers that wait for an animation (`UndoToast`'s fade-out, `TasksPane`'s row fold) read `useMediaQuery("(prefers-reduced-motion: reduce)")` and wait 0
- Manual order: `Item.order` / `Folder.order` are ranks (`src/lib/order.ts`, pure: `compareItemsManual`, `compareFoldersManual`, `placeNear`; ranked first, the rest by name). A note keeps its rank in its frontmatter (`order: 2048`, written only when set); folders have no file, so ranks live in `<vault>/.folder-order.json`, always written whole from the folders state (`writeFolderOrder`, so renames and deletes leave no stale keys) and read by `loadVault`. `placeNear` returns one rank (the middle) or renumbers the list when a neighbour has no rank, the gap is gone, or the list is shown by name or date. Ranks are written with `updateItem(id, { order }, false)` (no new edited date). `updateItem` clears `order` when `folderId` changes unless the caller passes `order` (the rename cascade does, since the note stays in the same folder); `moveItem` clears it too and rewrites the file. The sidebar's order menu is Manual / Name / Recent (`graphene.sort`); dropping between rows in Name or Recent switches to Manual, numbered as shown. The folder picker and "Move to" list folders in manual order
- Updater: `tauri-plugin-updater` + `src/hooks/useUpdater.ts` (checks about 5s after launch, never in dev builds; the user installs from `UpdateDialog`). The version number and the manual check live in Settings > About (`AboutPanel`); the sidebar header shows only the Update pill, and only while an update exists. `UpdateDialog` is rendered by `App` (the pill and About both open it; About closes Settings first). The hook runs in `App`, not `MainApp`: switching vaults remounts `MainApp`, and the Update pill and the launch check must survive that. `App` also owns the editor's `flushRef`, the window-close flush, `useVaults` and the Settings state, which is why `SettingsDialog` sits outside the remount key. Windows only (NSIS, passive install). Endpoint is `latest.json` on the GitHub releases. The private signing key lives outside the repo in `%USERPROFILE%\.tauri\`; CI uses the secrets `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`; the public key is in `tauri.conf.json`

# GitNexus — Code Intelligence

This project is indexed by GitNexus as **graphene** (619 symbols, 1132 relationships, 51 execution flows).

> Index stale? Run `node .gitnexus/run.cjs analyze --index-only` from the project root — it auto-selects an available runner. No `.gitnexus/run.cjs` yet? Bootstrap with `npx`, `bunx`, or `pnpm dlx` — e.g. `bunx gitnexus@latest analyze` (npm 11 npx crash; #1939).

## Always Do

- **MUST run impact before editing.** Use `impact({target: "symbolName", direction: "upstream"})` or `node .gitnexus/run.cjs impact "symbolName" --direction upstream --repo .`; report callers, processes, and risk. Never substitute grep for graph analysis.
- **MUST analyze graph changes before committing.** Use `detect_changes({scope: "all"})` (MCP) or `node .gitnexus/run.cjs detect-changes --scope all --repo .` (CLI fallback). `partial: true` or `truncated: true` is not a clean check — a zero means unseen, not unaffected; re-run it. For regression review: `detect_changes({scope: "compare", base_ref: "main"})` or `node .gitnexus/run.cjs detect-changes --scope compare --base-ref "main" --repo .`.
- MUST warn on HIGH/CRITICAL `risk` pre-edit; never use `riskSharedAxes` to waive a HIGH/CRITICAL `risk` warning. Compare File/symbol: MCP File omits axes; Graph-RAG expands File.
- **MUST treat `risk: UNKNOWN` as unresolved, not as low.** An empty caller set is not evidence the symbol is unused — it can also mean the callers are not resolvable by the index (plain-object property access, dynamic dispatch, cross-language calls). `impact` pairs `UNKNOWN` with a `riskNote` saying so. Confirm with a text search before treating the symbol as safe to change or delete; do not proceed on the strength of a zero.
- **MUST use `query({search_query: "concept"})` for concepts/flows, `context({name: "symbolName"})` for a named symbol, or `impact` for blast radius, on read-only callers, dependencies, imports, or execution flow.** Graph first; text search only for empty/`UNKNOWN`/literals.
- For security review, `explain({target: "fileOrSymbol"})` lists taint findings (source→sink flows; needs `analyze --pdg`).

## Never Do

- NEVER edit a function, class, or method before MCP/CLI impact analysis.
- NEVER ignore HIGH or CRITICAL risk warnings from impact analysis, and never read `UNKNOWN` as an all-clear — it means the walk could not answer, which is the one verdict that requires confirming by other means.
- NEVER rename symbols with find-and-replace — use `rename` which understands the call graph.
- NEVER commit before MCP/CLI graph change analysis.
